# 系统职责与接口

## 总体分工

平台由驾驶终端、中心实验服务和操作者 Launcher 协作完成实验。单机阶段这些功能运行在同一台机器，多机阶段按职责部署到不同机器。

| 部分 | 主要职责 |
| --- | --- |
| CARLA Unreal 原生端 | 世界运行、车辆物理、本地驾驶输入、原生画面、车辆表现与状态输出 |
| DRISCA Python 客户端 | 将 JSON 接口组织成研究代码可直接调用的方法与数据 |
| 中心实验服务 | 实验编排、车辆归属、状态汇总与转发、环境协调、数据保存 |
| Python 交通模型 | 路线与交通行为计算，生成指定车辆的运动目标或控制量 |
| Launcher | 配置编辑、启动停止、实验操作、状态展示、数据管理与导出 |

中心实验服务可以从现有 Launcher 后端扩展。单机原生驾驶先完成实际链路，多机阶段再加入终端管理与状态转发。

## 专用接口

最终由 DRISCA 的 JSON 接口覆盖项目所用能力，Python 业务代码使用自己的数据结构。原生端直接接入 CARLA 与 Unreal 已有实现。

接口分为实验操作和逐车操作。实验操作提供场景准备、开始、结束、视图调整和录像等能力；逐车操作提供车辆创建与销毁、状态读取、控制来源切换和控制输入。研究模型可以直接控制指定车辆。

需要迁移的现有能力包括地图与出生点、车辆目录和生成、天气、相机与镜面布局、驾驶状态、道路与车道信息、IMU/GNSS、碰撞与压线、Recorder 和已有回放操作。压线和道路计算包含原客户端承担的工作，迁移时复用现有算法并保持数据含义。

单机通道采用 WebSocket，由 simulator worker 连接 Unreal，JSON 承载命令、结果与事件，固定二进制承载全车运动与主车研究快照。状态在 PostPhysics 汇总，`frame_no` 表示刚结束物理更新的世界帧，`timestamp`、`wall_time`、位姿和速度来自同一次采样。worker 连续读取最新快照，按 `frame_no` 丢弃重复帧。读取间隔属于当前实现参数，采样结果保留实际帧号和时间。

成功调用 `driving_view.start` 的连接持有当前活动视图。活动期间再次调用 `start` 返回 `driving view is already active, use update to change it`，配置调整统一使用 `update`。

普通调参连接断开只释放该连接。控制连接意外断开时，原生端停止驾驶输入和视图并恢复默认自由视角，Python 侧抛错退出，Launcher 将会话记为 `aborted`。正常 `stop` 释放控制归属并保留 Unreal，下一次实验由新连接重新调用 `start`。

本机调参工具沿用已有入口。产品界面的调整通过 Launcher 与 worker 执行。业务消息与连接方向分别描述，后续接口选型见[待讨论事项](./04-Decisions.md)。

Python 已通过自有客户端访问原生 API，移除了官方 carla 包和专用 wheel，原生端继续复用 CARLA 内部能力。官方 Traffic Manager 宿主方案取消，自研 Python 交通模块放在 `src/drisca/traffic/`，道路、信号与 `external` 批量控制接口为其提供基础。单车完整流程已在编辑器版 `Town10HD_Opt` 与 `Singapore_Intersection` 验证通过。

天气配置的命名预设来自原生环境目录，代表一套完整的全局环境值；`preset_name` 为 `Custom` 时使用各项数值参数。界面选择预设后填入对应参数，修改任意参数会自动切换到 `Custom`。脚本需要修改预设中的某个参数时，先读取该预设参数，再以 `Custom` 提交修改后的完整天气。强度统一为 0 到 1，局部球雾单独配置。

## 车辆如何控制

每辆车有一个负责计算其实际运动的来源。单机时，来源可以是本地人工驾驶或模型；多机时，被试车辆由对应终端负责，背景车辆由中心交通服务负责。控制来源切换与驾驶模式操作集中处理。

人工驾驶直接作用于本地车辆。研究模型可以提交油门、刹车与转向，也可以给出目标速度、加速度或路线，由相应车辆控制器执行。目标控制从具体实验需要的简单能力开始实现。

外部轨迹可以直接驱动车辆位姿，并补齐车轮、转向和车灯表现。物理执行与轨迹播放分别描述实际运动来源，研究记录保留所用方式。

交通行为模型和车辆执行分开。跟驰模型决定加速度，换道模型决定目标车道或轨迹；车辆控制器负责将目标落实为运动。使用物理执行时，模型读取实际运动结果继续计算。

## 两阶段实验生命周期

实验准备时，Launcher 启动或连接 CARLA，应用主机窗口参数并显示默认观察视角。运行程序保留，供一批实验使用。

每次实验开始时应用场景配置，创建实验车辆与所需组件，绑定本地驾驶视图，启用输入和记录。停止时完成数据与录像收尾、释放实验对象并恢复默认视角，CARLA 继续运行。

配置沿用现有归属：主机配置负责窗口和服务；输入配置负责按键与设备；实验预设负责场景、车辆与相机；本次实验设置负责被试和保存选项。最终运行配置由程序合成。

## 多终端协作

各驾驶终端运行本地 CARLA Unreal，计算和显示本机车辆。中心服务接收各来源状态，形成供实验操作和转发使用的全局视图。其他车辆在本机按接收状态更新和显示。

各终端的 worker 连接中心服务，承担本机与中心之间的状态转发和命令执行。本地 worker 到 Unreal 的驾驶通道继续沿用单机方式，中心连接在多人阶段加入。

中心统一管理实验车辆身份、地图版本、坐标约定和交通信号等共享环境。各车的运动由其所属来源计算，副本跟随来源状态。多机首次实现聚焦两名驾驶者互相看到对方及集中记录。

原生端提供最新连续状态，接收端使用实际到达的新状态。车辆显示平滑与数据存储各自处理，存储保留来源端数据，便于区分真实计算结果和显示效果。

## 数据保存

单机阶段延续已有数据库与后台写入。进入多机阶段后，中心统一保存来源终端、车辆身份、原始帧号和时间、接收时间、驾驶人输入与车辆实际状态。

各终端帧号属于各自世界；相互关系由时间信息与实验身份描述。数据允许存在采样间隔，记录实际读到的状态。碰撞、压线和实验操作等离散事件分别保留来源与发生信息。

各终端独立执行物理时，接触结果可能不同。初期记录来源端实际事件和车辆运动，碰撞统一判定的需求在相应研究出现时确定。
