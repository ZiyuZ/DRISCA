# 目标与使用场景

## 平台定位

DRISCA 面向驾驶行为与交通交互研究。研究人员通过可控的道路、交通参与者与实验操作，观察人的驾驶行为及车辆之间的相互影响。自动驾驶模型作为一种车辆控制来源接入，与人工驾驶和背景交通共同参与实验。

核心目标是让实验人员方便地组织和操作实验，让研究人员能够直接编写车辆行为。研究代码可以指定路线、速度和行为，也可以直接提交车辆控制量。CARLA 提供实际运动、场景表现和必要的传感器能力。

## 主要场景

单人实验中，被试在驾驶终端操作主车，主试通过 Launcher 设置场景、控制实验指令并观察状态。实验结束后集中浏览与导出数据。

交通行为实验中，研究人员为其他车辆编写跟驰、换道、汇入、让行或特定实验动作。车辆可以采用不同的控制模型，实验人员能够修改其中一辆车的行为，并观察被试与交通环境的响应。

多人实验中，两至三台驾驶终端分别控制本机被试车辆，使用相同地图。各终端通过中心服务交换车辆状态，本地显示其他车辆；中心机器统一组织场景、运行背景交通并保存数据。

外部轨迹或交通仿真接入时，平台根据给定运动数据呈现车辆。车辆位置、动画与物理执行方式根据实验用途选择。

## 交互与表现

被试车辆使用本地原生画面与输入，保证直接的驾驶响应。主视图与三路独立后视镜保留不同视点，能够表现车门、车身和附近车辆的遮挡。

车辆表现包括车轮滚动、转向和车灯等已有能力。正常驾驶通过车辆物理自然产生运动；轨迹驱动的车辆补齐相应动画。远端车辆根据收到的运动状态平滑显示。

实验机目标为一个 5760×1080 无边框窗口横跨三屏，主视图和三路后视镜按 60 FPS 目标实现。开发机使用适合当前屏幕的窗口尺寸。实际帧率与驾驶响应分别通过运行验证。

## 精度取向

平台采用异步运行，接受采样遗漏和终端之间一定程度的状态延迟。各条数据保留实际时间、帧号和来源，分析使用这些信息解释采样间隔与交互时序。

实验对精度的要求由研究指标决定。一般交通呈现、跟驰趋势与精细反应时间分析采用各自合适的判断标准。集中存储保留原始来源信息，方便研究人员选择分析方式。

## 交付目标

发布时提供 Launcher、修改后的 CARLA 运行程序、必要资源、配置和私有 Python 运行环境。普通操作者通过 Launcher 开展实验；研究人员使用随程序提供的 Python 环境运行和修改实验脚本。

现有 Web 界面继续支持本机桌面和局域网操作。界面实现与驾驶渲染分别演进，交付以完整安装或解压后可启动为目标。
