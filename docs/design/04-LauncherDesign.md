# 管理端界面与功能设计

`launcher` 是操作者准备、控制和查看实验的入口。界面采用同一套 Web 页面，在实验主机的 pywebview 窗口或局域网浏览器中使用。操作者可以在主机旁用平板控制实验。被试使用 `simulator` 的驾驶画面与独立 HUD 页面。

## 界面形式

桌面采用 pywebview 无边框窗口，自绘标题栏与窗口按钮。网页与桌面共用标题栏，显示应用名称、当前页面和连接地址入口，桌面模式额外显示原生窗口操作按钮。页面内容、侧栏和对话框使用统一的圆角样式，原生窗口的圆角随桌面集成实现。

交互原型使用 Basecoat 与 Alpine.js，以静态 HTML 展示页面、表单和交互，固定采用桌面窗口样式。标题栏高度约 38px。正式浏览器入口沿用页面布局并隐藏窗口操作按钮。正式前端使用 Vite、React、TypeScript、Tailwind CSS 和 shadcn/ui，由 Bun 管理依赖，构建产物由 Python 服务提供。

应用占满视口，标题栏和侧栏保持固定，各页面内容在内部滚动。实验控制页优先同屏呈现实验所需的操作与状态，日志在独立区域内滚动。侧栏支持收起，系统设置固定在底部，CARLA 连接与驾驶端状态集中在左下角。标题栏的连接入口弹出操作者控制台与被试 HUD 的地址和二维码。

## 页面划分

| 顺序 | 页面 | 主要用途 |
| --- | --- | --- |
| 1 | 实验控制 | 实验启停、状态监控、实验动作、打点与日志 |
| 2 | 实验配置 | 地图、天气、车辆、出生点与预设管理 |
| 3 | 辅助工具 | 画面布局与相机安装 |
| 4 | 实验数据 | 实验记录、日期筛选、勾选导出与录像回放 |
| 5 | 系统设置 | 主机连接、显示、存储、键盘与方向盘设置 |

## 实验控制

实验控制页左上方使用一张固定尺寸的主卡片呈现实验生命周期，右侧放置实验打点。主卡片分为固定标题区、内容区与底部操作区。启动前显示预设、被试编号、备注、保存与录像选项；启动后切换为驾驶状态。标题在同一位置淡入淡出，内容使用短时透明度与位移过渡。主按钮保持同一位置，从“开始实验”切换为“结束实验”。结束实验调用后端的正常停机流程。连接状态集中在侧栏，显示 CARLA 与子进程连接情况。

管理端启动时尝试连接 CARLA 一次，失败后显示未连接状态，由操作者点击侧栏连接按钮再次尝试。侧栏显示“CARLA 服务器已连接”或未连接状态，悬停显示配置的 CARLA 地址与端口，并单独显示驾驶端的启动与运行状态。未连接时，开始实验和开始回放按钮禁用，悬停提示先连接 CARLA。回放在实验运行期间同样禁用。

状态区显示车速、限速、挡位、驾驶模式、接管请求和驾驶端运行情况。油门、刹车、转向各展示一组实际车辆控制值。研究数据继续分别记录驾驶人输入与实际控制。

实验指令独占一行，按钮从已知指令库中选择。指令库由 Python 代码声明可执行指令、名称、参数类型、约束与执行方式，应用初始化时读取。预设保存指令标识、参数和按钮名称。停止时，点击按钮编辑这条指令，右上角提供“添加指令”；运行时，点击按钮执行所选指令。编辑窗口只提供已知指令及其参数。

“请求接管”指令包含接管状态与可选语音参数，一次点击完成请求和播报。切换人工驾驶后解除接管请求。控制命令由模拟器应用后上报事件，管理端统一记录。普通调整失败时展示错误，控制权等关键操作失败时停止实验。

实验打点使用独立卡片，按预先定义的名称生成按钮，点击即写入一条打点事件。默认提供进入路段、离开路段、任务完成和异常情况，实验开始由启停流程记录。实验开始前，打点区域显示锁定提示和禁用状态，实验指令保持可编辑。

日志和事件日志在实验控制页查看。日志显示子进程输出与错误；事件显示帧号、时间、事件名称、来源和详情。关闭保存时显示“调试运行”，实时状态、日志和事件照常更新。

连接入口分别提供操作者控制台和被试 HUD 的局域网地址。HUD 展示车速、限速、挡位、转向和驾驶模式。

## 实验配置

实验配置管理 `configs/presets/*.toml`，支持新建、切换、保存、另存与删除预设。世界设置包含地图、重载地图选项、同步模式、世界推进频率和天气。地图、车辆和实验预设提供搜索选择；下拉选项显示箭头。天气通过独立对话框选择预设并调整参数，连续数值采用滑动条与数字输入联动，详细天气项折叠展开。

车辆设置包含蓝图、角色名、默认限速、道路动态限速与启动自动驾驶选项。出生点保存六个位姿字段，可以从地图出生点中选择、手动填写，或从运行中的最新遥测拾取当前位置。限速使用滑动条与数字输入联动，界面单位为 km/h，保存时换算为 m/s。

一份预设同时包含场景、车辆和相机参数。相机安装参数和画面布局在辅助工具中调整，与实验配置使用当前选中的同一份预设。

## 辅助工具

辅助工具使用固定的二级标签切换画面布局和相机安装，标签栏右侧显示当前编辑的预设并支持切换，内容在标签下方滚动。

### 画面布局与相机安装

画面布局在同一张卡片中呈现画布与参数。分辨率选择位于画布左上角，右上角提供后视镜显隐图标与悬停帮助。操作者拖动后视镜调整位置，拖动缩放手柄修改尺寸，也可直接输入像素值。后视镜使用编号与画面外标签对应，宽屏比例下保持标签清晰。位置和尺寸对应实际驾驶窗口，保存时沿用现有相机配置。卡片底部提供恢复预设、应用和保存操作。

相机安装单独调整四路相机相对车辆的位置、旋转和 FOV，每项使用滑动条与数字输入联动。位置以车辆包围盒中心为 0%，各方向边界为 ±100%；数字框允许填写车身范围外的位置。配置保存比例坐标，1 对应 100%，由 simulator 使用实际车辆包围盒换算为安装坐标，换算包含包围盒中心与旋转。相机旋转与 FOV 使用角度。

管理端显示百分比与位置示意。运行时可由 simulator 提供当前车辆的包围盒供图形展示；车型尺寸表可按离线编辑需要导出。

顶视图按车身尺寸显示相机位置、朝向与水平视野角；侧视图显示安装高度和俯仰朝向。视图切换放在画布左上角，与画面布局统一。画布撑满卡片顶部与图例之间的区域。拖动相机编号修改位置，顶视图调整前后与左右，侧视图调整前后与高度，再通过滑动条和数字框微调。示意图与参数同步更新。右侧参数卡片底部左侧提供恢复当前相机预设的按钮，应用和保存位于右侧。这些参数属于实验预设；画面布局描述后视镜在驾驶屏幕上的位置和大小。

宽窗口下，相机示意与参数两张卡片保持等高；窄窗口下自动改为上下排列。

实验运行时，操作者将修改应用到模拟器，查看实际驾驶画面的效果。参数应用后由模拟器上报调整事件。原型中的示意图用于展示画面布局。

调好后可覆盖当前预设或另存为新预设。运行中的相机状态与本次启动配置分别保留，启动配置和调整事件共同描述实验条件。

## 实验数据

实验数据使用实验记录和录像回放两个固定标签。

### 实验记录

默认显示最近 30 天的会话，允许修改日期区间，并按被试、会话编号和状态筛选。会话表格在内部滚动，日期、筛选、选择和导出控件保持固定。表头复选框选择当前筛选的全部会话，界面持续显示已选数量。日期或状态筛选变化后，已有选择继续保留，操作者可清空后重新选择当前筛选结果。

总会话数、筛选结果与已选数量统一放在表格内部工具栏。

列表显示会话编号、起止时间、时长、地图、车辆、记录帧数和备注。详情展示本次完整运行配置、事件日志和记录中的实际备注，空备注保持为空。

点击导出后，后端将选中会话的 `sessions.csv`、`data.csv` 和 `events.csv` 写入实验主机配置的导出目录，通过 `session_id` 关联。每次导出使用独立子目录，界面显示进度和完成路径。浏览器与桌面使用同一流程。

### 录像回放

应用管理的录像按表格分页显示，支持名称搜索。点击行选择录像，选中样式与悬停样式分别显示，回放设置中显示当前录像。操作者可以查看摘要或详细信息，设置回放起点、时长、倍速与跟随车辆，再调用 CARLA 回放。回放由已启动的 CARLA 服务端执行，安排在实验结束后进行。基础版先完成录像选择与回放控制。路网工具随相关需求推进。

## 系统设置

标签栏固定，当前标签的设置内容在下方独立滚动。机器设置管理 `configs/machine.toml`：CARLA 地址与端口、连接超时、驾驶窗口分辨率和显示选项、目标帧率、管理端监听地址与端口、数据库、录像与导出目录、语音与日志选项。导出目录使用 `MachineConfig.export_dir`，在管理端接入时同步补入配置模型。

控制设置管理 `configs/control.toml`：方向盘启用、设备编号、按钮编号日志，以及键盘和方向盘的动作绑定。每个动作在每种设备上选择一个按键，界面显示名称，配置保存枚举字符串。按键说明与配置共用名称表。方向盘随动字段保留，功能安排在后续硬件工作中实现。

配置修改用于下次实验启动；服务监听设置在管理端重启后生效。配置组成和保存规则见[配置管理](../guide/05-Configuration.md)与[配置模型](./08-ConfigurationModels.md)。

## 后端与窗口

Python 后端负责实验编排、配置读写、数据访问和模拟器通信，浏览器通过 HTTP 提交操作，通过 SSE 接收状态。桌面与浏览器共用这些接口，通信方案见[管理端前后端通信](./10-LauncherWeb.md)。

子进程使用 Python 标准库 `subprocess` 管理，并加入 Windows Job Object。桌面关闭按钮调用同一套实验停机和管理端退出流程；浏览器关闭标签页只断开该页面连接。具体生命周期见[系统架构](./01-Architecture.md)。

## 交互反馈

应用内操作统一使用图标按钮或文字按钮。添加指令使用加号图标按钮，其他卡片操作使用带悬停反馈的文字按钮。滚动条使用无箭头的细滑块，滚动或指针靠近轨道时显示，停止操作后自动隐藏。

普通界面文字保持不可选中。输入框、日志、数据表和导出路径等数据区域保留文字选择，便于填写和复制。

标题栏和侧栏共用一种浅灰蓝色，工作区使用另一种浅灰色，卡片保持浅色。侧栏收起与展开使用不同图标，窗口操作使用统一尺寸的 SVG 图标。按钮悬停、侧栏伸缩、对话框打开和主卡片内容切换使用短时过渡；系统设置减少动态效果时跟随系统偏好。通知使用固定水平位置的淡入淡出。操作帮助集中在布局与相机坐标等必要位置，通过即时悬停或键盘焦点浮层查看。对话框遮罩覆盖标题栏下方工作区，标题栏保持清晰；背景业务控件暂停响应，原生窗口管理由桌面壳处理。禁用控件显示灰色状态，打点区域同时提供锁定图标和可用条件提示。

## 组件约定与原型

定稿原型位于 `prototypes/launcher/`。原型采用 Basecoat 标准 Dialog、Button、Tooltip、Switch、Tabs、Command 与 Toast，Alpine.js 管理业务状态。Dialog 使用原生模态元素的标题、正文和页脚结构，正文独立滚动，焦点与 Esc 交由组件处理。

正式前端优先采用 shadcn/ui 标准组件，保留原型已确认的紧凑布局、配色和操作流程。相机画布、拖拽换算及实验状态切换属于业务交互。组件样式调整集中在主题与必要布局，通用控件遵循组件公开结构和行为。
