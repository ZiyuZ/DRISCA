# 快速开始

本文按“准备环境 → 打开管理端 → 启动 CARLA → 准备实验 → 驾驶与记录 → 结束与导出”的顺序完成一次单机实验。

Launcher 是主试使用的管理窗口，CARLA Unreal 是被试使用的驾驶窗口。一组实验启动一次 Launcher 和 Unreal，可以连续开始、结束多次实验。结束单次实验后，Unreal 保留并回到默认自由视角。

当前原生驾驶流程使用键盘。方向盘配置保留，原生驾驶端的方向盘接入后续完成。首次运行先使用适合开发机屏幕的窗口，例如 1600×900；三屏实验机再设置 5760×1080 并调整窗口位置。

## 1. 准备环境

准备 Windows 机器，并安装 uv、Bun、just 和 Edge WebView2 Runtime。项目使用 Python 3.14，由 uv 管理解释器和虚拟环境；桌面管理窗口通过 WebView2 显示界面。

CARLA 运行程序需要包含 DRISCA 原生驾驶模块和实验所用地图。可以使用源码编译后的 UE 编辑器版，也可以使用包含该模块的 CARLA 打包版。Python 客户端 wheel 与服务端配套，当前仓库通过 `pyproject.toml` 引用 `vendor/carla/carla-1.0-cp314-cp314-win_amd64.whl`，安装依赖前确认该文件已放入对应目录。

打开终端，进入 DRISCA 仓库根目录，安装依赖并构建管理界面：

```bash
uv sync
bun install --cwd frontend --frozen-lockfile
just frontend-build
```

以上准备在首次使用时完成。更新 Python 依赖后重新运行 `uv sync`，更新前端依赖或界面代码后重新安装相应依赖并构建界面。

## 2. 首次打开管理端

在仓库根目录运行：

```bash
just launcher
```

Launcher 会打开桌面窗口，并自动从示例生成缺少的配置文件，已有配置继续保留：

| 文件 | 用途 |
| --- | --- |
| `configs/machine.toml` | 本机 CARLA 路径、连接、驾驶窗口和数据目录 |
| `configs/control.toml` | 键盘和设备按键绑定 |
| `configs/presets/basic.toml` | 首个实验预设，保存场景、车辆、相机、指令与标记 |

首次打开后先按下一节填写程序路径，再通过 Launcher 启动 CARLA。配置归属与各字段说明见[配置管理](./05-Configuration.md)。

## 3. 配置并启动 CARLA

### 填写运行程序与显示参数

打开“主机配置 → 连接与服务”，在“Unreal 运行程序”卡片选择运行版本并填写路径。

| 运行版本 | 需要填写 |
| --- | --- |
| UE 编辑器版 | `UnrealEditor.exe` 路径，以及 CARLA 的 `CarlaUnreal.uproject` 路径 |
| CARLA 打包版 | 打包后的 `CarlaUnreal.exe` 路径 |

路径指向具体文件，两种版本的路径分别保存，后续通过运行版本切换。编辑器版会以游戏模式启动 CARLA。地图准备见[自定义地图](./03-CarlaUE.md)。

在同一页确认服务地址与端口。本机启动使用以下默认值：

| 项目 | 默认值 |
| --- | --- |
| CARLA 地址 / RPC 端口 | `127.0.0.1:2000` |
| CARLA 流传输端口 | `2001`，由 RPC 端口加一得到 |
| 驾驶接口端口 | `7910` |
| Launcher 服务监听地址 / 端口 | `0.0.0.0:7900` |

打开“主机配置 → 驾驶显示”，填写窗口分辨率、X/Y 位置、全屏或无边框选项。窗口位置支持负坐标，用于将驾驶窗口放到主屏左侧的显示器。实际桌面尺寸还受 Windows 显示缩放影响。

在“数据存储”标签确认数据库、录像和导出目录。相对路径以仓库根目录为起点，默认目录见本文的数据位置表。

配置会自动保存，标签栏右侧显示保存状态。数字输入在失焦或按 Enter 后提交。修改启动参数后，下次启动 Unreal 生效。

### 启动并等待连接

点击左下角“Unreal”状态按钮，在对话框中选择“启动 Unreal”。Launcher 会启动程序并等待 CARLA 世界和驾驶接口就绪。等待 CARLA 服务器已连接后，再准备实验。

如果 CARLA 已由其他方式启动，点击左下角 CARLA 状态按钮，填写地址和 RPC 端口后点击连接。该程序同样需要包含原生驾驶模块，并使用与主机配置一致的驾驶接口端口；外部启动的进程由原启动方关闭。

## 4. 准备实验预设

点击标题栏“实验预设”，选择 `basic`，也可以新建自己的预设。在同一对话框确认“保存数据”和“录像”选项。首次完整试运行建议开启保存数据，便于结束后核对记录；临时调试可关闭保存。录像随保存数据总开关启用。

打开“方案配置”，依次完成以下设置：

1. 在“场景与车辆”选择服务器提供的地图和车辆蓝图，设置初始天气与驾驶模式。首次手动驾驶关闭“启动后开启自动驾驶”。
2. 从所选地图的出生点列表选择车辆位置。若列表尚未对应目标地图，先点击左下角 CARLA 状态按钮，在场景控制对话框中切换到目标地图，等待加载完成后再选择出生点。
3. 在“相机安装”调整主视图和三个后视镜的位置、角度及视野。位置按车身包围盒比例填写，界面中的 ±100% 对应包围盒边界。
4. 在“指令与标记”准备本次需要的实验指令和打点按钮，例如请求接管、进入路段、任务完成。

地图和车辆列表来自已连接的 CARLA。基础预设中的地图与出生坐标用于初始配置，首次使用时应选成当前场景中的实际位置。

画面中各后视镜的显示位置和尺寸在“主机配置 → 驾驶显示”调整，保存到本机配置。相机安装参数保存到当前实验预设。选择天气预设后修改任意参数，天气类型会自动切换为“自定义”。

实验启动时应用预设中的地图与天气。左下角场景控制对话框中的手动环境调整用于当前 CARLA 场景，下一次实验仍按所选预设启动。地图切换在实验空闲时进行，加载期间控制台显示等待界面。

## 5. 开始驾驶与执行实验

回到“控制台”，在驾驶状态面板填写被试编号，确认实验预设与保存选项后点击“开始实验”。等待驾驶端进入运行状态，Unreal 会创建实验车辆并切换到驾驶视角。

点击驾驶窗口使它获得键盘焦点。默认常用按键如下，完整绑定可在“输入配置 → 键盘”查看和修改：

| 按键 | 操作 |
| --- | --- |
| `↑` / `↓` | 油门 / 刹车，持续按住逐渐增加 |
| `←` / `→` | 左转 / 右转 |
| `Q` | 切换前进与倒车 |
| 空格 | 切换手刹 |
| `P` | 切换人工驾驶与自动驾驶 |
| `\` | 接管车辆，切回人工驾驶 |

按键配置在每次实验开始时传入驾驶端，修改后于下一次实验生效。主试在 Launcher 观察速度、控制量和日志，点击实验指令执行操作，点击打点按钮保存对应事件。请求接管指令可同时触发配置好的语音提示。

键盘反斜杠表示驾驶人主动切回人工驾驶，只切换模式并记录事件。操作者点击 Launcher 的“请求接管”指令时，由 Launcher 播放该指令配置的语音。

运行期点击驾驶状态卡片上的天气图标，可即时调整当前天气。调整相机安装或后视镜布局后，点击“应用到实验”更新当前画面；配置页的自动保存同时保留下一次实验所用设置。

## 6. 结束、检查和导出数据

点击“结束实验”开始停机，随后可在对话框填写本次备注或跳过。等待驾驶端退出、会话收尾完成，Unreal 恢复默认自由视角后，可以填写下一个被试编号并再次开始实验。

打开“数据管理 → 会话记录”，按日期、状态或被试编号找到本次记录，点击查看详情，核对会话状态和记录帧数。勾选需要的会话后导出，界面显示导出进度与结果路径。筛选结果可以整体选择，表格内容在内部滚动。

默认数据位置如下：

| 路径 | 内容 |
| --- | --- |
| `data/experiments.sqlite3` | 会话、驾驶数据与实验事件 |
| `data/recordings/` | 开启录像时产生的 CARLA 录像 |
| `data/exports/` | 导出任务生成的结果目录 |
| `.cache/logs/carla-unreal.log` | Launcher 启动的 Unreal 日志 |

关闭保存的实验结束后，可以直接继续下一次实验。保存实验结束后，可在会话记录中查看与导出数据。需要回放时，在“数据管理 → 录像回放”选择应用维护的录像，并保持 CARLA 已连接、实验处于空闲状态。

一组实验全部完成后，在左下角 Unreal 对话框关闭程序，或直接关闭 Launcher。关闭 Launcher 时会先结束当前实验，再回收由它启动的 Unreal。

## 7. 后续日常使用

环境和配置准备好后，每次进入仓库根目录运行 `just launcher`，启动 Unreal，选择实验预设并填写被试编号，即可开始实验。结束后检查记录并导出本组数据。

启动或实验出错时，先查看控制台的运行日志和左下角状态。Unreal 启动失败时查看 `.cache/logs/carla-unreal.log`；Python 依赖安装失败时核对客户端 wheel；程序路径和端口通过主机配置调整。进一步处理见[常见问题](./04-FAQ.md)。

需要通过终端操作时，保持 Launcher 运行，在另一个终端调用命令，完整说明见[管理端命令行](./06-LauncherCLI.md)。

## 浏览器与平板

标题栏的连接图标提供控制台和被试 HUD 链接与二维码。平板与实验主机连接同一局域网后扫码打开；默认地址形式为 `http://实验主机IP:7900/`，HUD 位于 `/hud`。需要开放 Windows 防火墙中的管理服务入站访问时，允许当前实验局域网访问对应端口。

仅使用浏览器控制时，在实验主机启动管理服务：

```bash
just launcher --web
```

保持该终端运行，浏览器中按本文步骤操作。关闭浏览器标签页后，管理服务和实验继续运行；结束实验组后在服务终端按 Ctrl+C 完成管理端停机。

## 开发与更新界面

修改 React 或 CSS 时使用：

```bash
just launcher --dev
```

该命令同时启动 Python 管理服务和 Vite，桌面窗口加载开发页面，前端修改后自动热更新。Vite 自动选择空闲本机端口并代理管理端接口，关闭窗口时一起回收。修改 Python 代码后重新启动命令。

单独调试前端可用 `just frontend-dev`，同时保持 Python 管理服务运行。前端静态检查使用 `just frontend-check`，构建正式界面使用 `just frontend-build`；Python 静态检查和文档检查分别使用 `just lint`、`just rumdl`。
